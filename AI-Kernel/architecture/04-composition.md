# Composition

> **状态**：待完善。本文档目前为架构骨架。

## 1. 定位

Composition 负责能力组合、依赖解析、快照和替换实现。

**核心架构原则**：Composition 管能力如何组合。

## 2. 组合的形式

- 多个 Capability 组合成一个新的 Capability。
- 临时组合（Temporary Composition）：用户在运行时临时编排，尚未固化。
- 固化组合（Saved Capability）：被保存为可复用的 Capability Definition。
- 嵌套组合：组合能力可以进一步被组合。

## 3. 关键规则

### 权利不提升（ADR-0005）

组合能力的权限范围是组成能力权限的交集或子集，不得自动扩展。

### 依赖解析

组合能力声明对组成能力的依赖。Runtime 在实例化时解析依赖，处理版本冲突。

### 快照（Snapshot）

Snapshot 记录组合在某个版本或时间点的依赖和实现状态，使组合可复现、可分享、可重建。

## 4. 实现替换

- 同一 Capability 可以有多个实现。
- 在接口契约兼容的前提下，用户或系统可以替换实现。
- 替换不影响组合的对外接口。
